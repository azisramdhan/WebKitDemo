What this page is for

Every button above crosses the boundary between the web view and the app. The page posts a message, Swift handles it, and anything that comes back arrives as a resolved promise. Nothing here talks to a network.

Bridge reference

1
showToast(text) — hands a string to the app, which draws it over the web view and fades it out. One way; nothing is returned.
2
openNativeScreen(name) — asks the app to present a screen by name. Unknown names are reported back instead of ignored.
3
requestNativeData() — the only call that answers. It returns a promise that settles once Swift replies with the device profile.
4
logout() — clears the stored token and pops back to the login screen. The web view is discarded with it.

How a message travels

1
The page calls a method on the injected Bridge object.
2
That method posts to a named message handler registered on the web view's content controller.
3
Swift receives the message, decides what it means, and acts.
4
For calls that answer, Swift resolves the promise the page is already holding.

Why the page is this long

It used to fit on one screen, which meant a screenshot captured all of it and nothing was ever left out of frame. This section exists so the page runs past the bottom edge, and a tool that captures it has to scroll to see the rest.
